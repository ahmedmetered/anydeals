# persona.md template

Copy into `<project>/outreach/persona.md` and fill every section. The agent may only
claim what is written here. Keep it honest and specific.

## Sender

- Name: (the human behind the emails)
- Role / company:
- Sending mailbox: (status: not created / warming / ready) — see mailbox checklist below
- Tone: one line, e.g. "warm, direct, peer-level, no vendor speak"
- Signature email 1: name + company only
- Signature email 2+: name + company + one link (booking or site)

## Product (the only claims allowed)

- What it is, one sentence, in the buyer's words:
- The 3 pains it removes (be concrete, not "saves time"):
- Proof points that EXIST (numbers, named outcomes, guarantees you can stand behind):
- Pricing (may be hinted from email 2, never in email 1):
- Offer/CTA of the sequence (demo, audit, teardown?) and its length:
- Booking method: calendar link / suggest times / ask preference
- Objection answers: "too expensive" / "we already use X" / "no time" / privacy:
- Things explicitly NOT claimable (roadmap, integrations, certifications you lack):

## ICP and channels

- Industries / segments:
- Company size and geography:
- Who receives the email (role; named person if known, else role inbox):
- Segment that should be EXCLUDED from email (belongs to phone/DM/in-person):
- Language of the prospects:

## Sending checklist (gates actual sending, never drafting)

1. Secondary sending domain (never the main brand domain), DNS set
2. Mailbox on it (Google Workspace or similar), app password stored by the user
3. Warmup 2-3 weeks before first send
4. Caps: max 50/day, business hours of the recipients' timezone
5. Opt-out handling and a real reply-to monitored by the user

## Status log

- (date) — persona created / updated, by whom, what changed
